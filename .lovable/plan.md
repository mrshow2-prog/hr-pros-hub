## What I found

I rendered both PDFs you attached and inspected their metadata:

- `cv_8` (modern) — `Producer: pdfme` ✅ generated by the new pipeline
- `cv_9` (classic) — `Producer: react-pdf` ❌ generated by the OLD `@react-pdf/renderer` pipeline (not pdfme at all)

So you're comparing apples to oranges right now: modern is rendering through pdfme, but the file you saw labelled "classic" still came out of react-pdf (likely a cached/older build of the page). On top of that, looking at the current `buildClassic` / `buildExecutive` / `buildCompact` / `buildSkillsFirst` code in `src/lib/cv/pdfme/exportModernPdfme.ts`, there are real execution bugs that would also produce ugly output even on a fresh run:

1. **No fonts are registered with pdfme.** `cvTemplateConfig` says classic/executive should use Times serif, but pdfme falls back to its default Helvetica/Roboto for everything → all 5 templates look the same typographically, and the visual identity of classic/executive is lost.
2. **`wrapLines` underestimates character width** (uses a flat 0.50em). With `letterSpacing` and bold characters (M, W) it underestimates by ~15–25%. pdfme then re-wraps text inside a too-narrow box, producing the "Sum m ary" / "Com petencies" / "Govern m ent" character-spacing artefacts.
3. **Two-column blocks (Compact) use two independent cursors** but advance the global `cursorY` only at the end → if either column overflows the page, schemas get pushed past `PAGE_H` without a `newPage()` call and bleed into nothing.
4. **Chip wrapping (Skills-First)** measures width with the same flawed 0.50em → chips overflow the right margin or wrap mid-word.
5. **`exportCVToPdf` is supposed to route everything through pdfme**, but the file you uploaded proves at least one path is still hitting `react-pdf`. The legacy `src/components/cv-builder/pdf/Pdf*.tsx` files are still in the repo and importable, which is why a stale tree can still produce a react-pdf output.

This is exactly the "execution problem, not library problem" you suspected.

## Plan — fix all 5 templates on pdfme, mirror the previews

### 1. Register real fonts in pdfme

In `src/lib/cv/pdfme/core.ts`, load NotoSerif + Inter (or DM Sans + Playfair, matching what the HTML previews use) and pass them via `generate({ template, inputs, options: { font } })`. Expose `FONT_SANS`, `FONT_SANS_BOLD`, `FONT_SERIF`, `FONT_SERIF_BOLD` and accept a `fontName` on every `addText` call. Update `cvTemplateConfig` so each template references one of these names.

### 2. Accurate text measurement

Replace the flat-char-width heuristic with per-font width tables (Helvetica/Times AFM-style widths are public and tiny). Account for `letterSpacing` in `wrapLines` and `textHeightMm`. This single fix kills the "Sum m ary" artefact across every template.

### 3. Per-template layout fixes

For each template, port the actual structure of the matching preview component instead of inventing a parallel layout:

- **Classic** — Times serif headings, thick 0.6 mm ink rule under the header, 0.3 mm gray rule under each section title, role/period flex row, single column, photo square top-left.
- **Executive** — Times serif, large name with negative letterSpacing, photo circle top-right, section titles in primary color, summary in a left-bar "quote" with the bar height exactly matching wrapped text height, ▸ bullets.
- **Compact** — header with right-aligned contact stack, full-width hairline rule, then the two-column row (summary 62% / skills+languages 38%). Wrap each column in a `measure-then-render` pass that flushes a `newPage()` if either column would overflow, then renders both columns top-aligned on the new page from the same baseline.
- **Skills-First** — sans heading, circle photo, no section divider but a slim hairline under the header, properly measured pill chips with rounded radius = height/2, `→` bullets, hairline separator between experience items.
- **Modern** — already good; only touch it to use the new font/measurement helpers so it stays consistent.

### 4. Pagination correctness

Refactor `core.ts` so every `addText` / `addImage` / `addRect` / `addLine` that is positioned via `cursorY` runs through `ensure(h)` before computing its absolute `y`. Two-column blocks must use a dedicated `withColumns([leftFn, rightFn])` helper that handles page breaks for both columns together.

### 5. Kill the legacy react-pdf path

Delete `src/components/cv-builder/pdf/Pdf{Modern,Classic,Executive,Compact,SkillsFirst,Router}.tsx` and `shared.tsx`, and remove `@react-pdf/renderer` from `package.json`. This guarantees no future build can accidentally produce a react-pdf file again, which is what bit you on `cv_9`.

### 6. QA loop

After the rewrite I will:
1. Generate one PDF per template from the same sample CV.
2. Rasterize each page to PNG with poppler.
3. Visually compare each rasterized page to a screenshot of the wizard preview for the same template.
4. Iterate until every template matches its preview.
